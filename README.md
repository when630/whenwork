# WHENWORK

개인용 프로젝트별 업무 관리 트레이 앱 (Windows, Electron).

여러 프로젝트를 오가며 일하는 1인 사용자를 위해 세 가지 공백을 메운다:

1. **할 일 캡처** — 글로벌 단축키(`Ctrl+Alt+Space`) 원라인 퀵캡처, 분류는 나중에
2. **재개 컨텍스트** — git 활동 + AI 요약으로 "마지막 작업 / 멈춘 지점 / 다음 액션 1개" 카드
3. **대기 추적** — waiting-for 항목과 경과일

"한 일"은 git에서 자동 수집하고, 손 입력은 "할 일"에만 국한한다. AI 가공은 `claude -p`(구독 OAuth)로 수행하며, AI 생성물은 언제든 버리고 재생성 가능하다.

## 실행

```bash
npm install        # postinstall이 트레이 아이콘을 굽는다
docker compose up -d   # PostgreSQL (localhost:5433) — 없어도 캡처는 동작 (로컬 큐)
npm start
```

실사용은 **설치본**으로 한다: `npm run build` → `dist/WHENWORK Setup <version>.exe`(사일런트 설치는 `/S`). 자동 시작은 **설치본에서만** 걸린다 — 개발 실행의 `electron.exe` 경로를 로그인 항목에 박아봐야 쓸모없기 때문이다. 설치본과 개발 실행은 `app.setName('whenwork')`로 **같은 `userData`(큐·설정)를 공유**하고 단일 인스턴스 락을 나눠 갖는다. 그래서 코드를 고쳐 `npm start`로 확인하려면 **트레이에서 설치본을 먼저 종료**해야 하고, 확인이 끝나면 다시 빌드·설치해야 실사용에 반영된다.

### 조작

- `Ctrl+Alt+Space` — 퀵캡처 토글. 저장해도 창은 열려 있어 연달아 던질 수 있고, `Tab`이면 오늘 뷰로. `#gw` 같은 약어를 **앞이나 끝에** 붙이면 인박스를 건너뛰고 그 프로젝트로 바로 간다(`오늘 할일 #gw` = `#gw 오늘 할일`) — 치는 동안 `#gw → GoWrite`로 어디로 가는지 보여주고, 없는 약어면 그때 알린 뒤 토큰을 제목에 남긴다(인박스에서 `E`로 고치면 된다)
- 트레이 클릭 — 오늘 뷰 토글(한 번 더 누르면 닫힌다). `Tab` 탭 전환 · `↑↓`(`jk`) 이동 · `Home`/`End`/`PgUp`/`PgDn` 점프 · `Space` 완료 · `E` 제목 · `D` 마감일 · `N` 메모 · `X` 삭제 · `U` 삭제 되돌리기 · `Enter` 재개 카드
- `?` — 전체 키맵. 하단 힌트에는 그 화면에서 자주 쓰는 것만 두고 나머지는 여기서 본다
- 이슈 탭 — 열린 이슈·PR을 프로젝트별로. `T` 오늘 할 일로 · `Enter`/`O` 원본. 탭 배지가 열린 건수다
- 창을 열면 오늘부터 보여준다 — 인박스에 쌓인 게 있으면 그쪽부터, 퀵캡처에서 `Tab`으로 오면 언제나 인박스
- 마우스로는 체크박스를 눌러 완료할 수 있다(나머지는 키보드)
- `/` 검색 — 제목·메모·프로젝트·대기 상대를 한꺼번에 훑는다. 탭을 옮겨도 유지되고 탭 숫자가 매칭 건수로 바뀌므로 어느 탭에 있는지 배지만 보고 알 수 있다. 검색어를 넣은 채 `Tab`이면 그 필터로 다음 탭을 본다. `Esc`로 해제
- 오늘 탭 — 맨 위에 오늘 일정 타임라인, 아래는 프로젝트별 할 일(급한 건 `D+2`·`오늘` 배지로 드러난다). `W` 대기로 넘기기 · `F` 마감 있는 것만 보기 · `H` 완료 기록(최근 7일, 체크한 항목 + git 커밋) · `M` 방금 그 회의의 후속 할 일 담기 · `O` 이슈에서 온 할 일을 원본으로
- 인박스 — `A` AI 분류 제안 → `Enter` 확정, `1~9` 직접 지정, `W` 대기로
- 프로젝트 번호 — `1~9`가 무엇인지는 본문과 하단 바 사이 고정 띠에 늘 서 있다(`1 GoWrite #gw`). 오늘 탭 그룹 머리글·대기 행·AI 제안 칩에도 같은 번호가 붙는다
- 대기 탭 — `Space` 회신 옴 · `P` 재촉함(경과를 그때부터 다시 센다 · `U`로 되돌리기, 30분 안 중복은 횟수를 올리지 않는다) · `1~9` 프로젝트 지정(대기 유지) · `N` 메모
- 프로젝트 탭 — `N` 추가 · `E` 이름 · `A` 약어 · `R` 리포 경로 · `Shift+↑↓` 순서 · `X` 보관
- 재개 카드 — AI 3문항(`claude -p`) + git 활동 + 내 이슈·PR/MR(작성·할당·리뷰 요청). `R` 재생성, `Enter`/`O` 브라우저로, `T` 그 이슈를 오늘 할 일로, `PgUp`/`PgDn` 스크롤
- 리뷰 탭 — `G` 초안 생성/재생성 · `←→` 주 이동 · `↑↓` 스크롤 · `O` 볼트 파일 열기
- 설정 탭 — 볼트 경로 · 백업 폴더 · 아침 알림 · 캘린더 URL. `Enter` 변경(빈 입력은 취소) · `X` 기본값으로(토큰이 박힌 값은 `y` 확인) · `B` 지금 백업 · `C` 캘린더 동기화 · `O` settings.json 열기
- 트레이 메뉴 — 주간 리뷰 초안 만들기, 지금 수집, 지금 백업, 자동 시작, 창 위치 초기화

`npm test` 단위 테스트 · `npm run smoke` 부팅 스모크(창을 띄우지 않고 탭을 한 바퀴 돌려 화면 로직까지 확인하며, 실사용 인스턴스와 부딪히지 않게 임시 `userData`로 돈다).

이슈·PR 동기화는 `gh`/`glab` CLI 인증을 그대로 재사용한다(`gh issue list`는 PR을 포함하지 않으므로 따로 긁는다). 프로젝트별 리포 경로는 DB `project.repo_paths`에 있다.

`X` 삭제는 표시만 하고 30일 뒤에 실제로 지운다 — 그 사이에는 `U`로 되돌릴 수 있다.

퀵캡처는 그때 보고 있던 창 제목을 함께 남긴다(인박스를 정리할 때 "이게 왜 여기 있지"를 푸는 단서이자 AI 분류의 근거다). 포그라운드를 그냥 읽으면 이미 우리 팝업이 앞에 서 있으므로, **우리 프로세스가 가진 창과 항상 위(topmost)로 떠 있는 창을 건너뛰고** z-order에서 첫 실제 창을 고른다 — z-order는 항상 위인 창을 전부 앞에 세우는 탓에, 그런 앱을 하나라도 띄워두면 실제로 무엇을 보고 있었든 답이 그 하나로 고정된다. 다만 포그라운드가 이미 실제 창이면 항상 위여도 그대로 쓴다.

재개 카드는 열 때가 아니라 **수집이 끝난 뒤에 미리** 만들어 둔다 — 열자마자 `claude -p`를 기다리지 않게 하기 위해서다. 다시 만드는 대상은 카드를 만든 뒤로 커밋이 들어온 프로젝트뿐이고(자료가 그대로면 같은 카드가 나온다), 그 커밋 수는 카드 머리에 「이후 커밋 N」으로 붙는다.

이슈는 이슈 탭이나 재개 카드에서 `T`로 오늘 할 일이 된다. 원본 이슈는 그대로 두고 로컬 할 일이 URL만 참조하므로, 이슈가 닫히면 「닫힘」 배지가 붙을 뿐 자동으로 체크되지는 않는다.

대기 항목은 `P`로 "재촉함"을 찍는다. 경과일이 재촉 시점부터 다시 세어지고 아침 브리핑도 그 기준으로 알린다 — 어제 찌른 건과 열흘째 방치한 건이 같은 숫자로 보이지 않게.

아침에 처음 앱이 도는 시점(기본 09:00, 설정 탭에서 변경)에 지연·오늘 마감·오래 기다린 항목·인박스 건수를 트레이 알림으로 한 번 알린다. 마감은 탭을 가리지 않고 센다 — 인박스·대기 항목에 넣은 마감도 함께 알린다. 그 넷이 모두 0이면 **열린 할 일 수를 대신 알린다**(「할 일 6건 (가장 오래된 건 5일째)」) — 이 넷은 전부 마감 같은 입력 습관에 기대는 값이라, 마감을 쓰지 않는 주에는 손에 일이 쌓여 있는데도 브리핑이 통째로 조용해졌다. 정말 아무것도 없는 날은 알리지 않고, 그 시각을 3시간 넘겨 켠 날은 조용히 넘긴다.

캘린더는 [Apps Script 웹앱](docs/apps-script-calendar.gs)을 15분마다 긁어 `cal_event`에 캐시한다. 오늘 일정은 오늘 탭 맨 위에 타임라인으로 선다 — "지금"이 어디쯤인지 점선으로 표시되고, 지난 것은 흐리게, 진행 중인 것은 초록으로 강조된다. 아침 브리핑과 주간 리뷰 재료에도 들어간다. 회사 Workspace가 iCal 비공개 주소를 막아 이 경로를 쓰며, 공개 iCal과 달리 캘린더를 공개하지 않고도 제목까지 받는다. 웹앱 URL에는 토큰이 들어 있어 설정 화면에는 가린 값만 보인다.

백업은 **하루 한 번 스스로** 남고, 주간 리뷰를 만들 때도 곁들여 돌며, 트레이·설정 탭에서 직접 돌릴 수도 있다. `userData/backups`에 전체 테이블을 담은 JSON으로 쌓이고 최근 8개만 남는다 — 데이터가 도커 볼륨 하나에만 있는 상태를 없애기 위한 것이라 `pg_dump`나 docker에 기대지 않는다. 실패하면 알림 한 번을 띄우고 트레이·설정 화면에 마지막 성공 시각보다 실패 이유를 먼저 보여준다(그날은 다시 두드리지 않는다).

본문 글꼴로 [Pretendard](https://github.com/orioncactus/pretendard)(OFL)를 `renderer/fonts`에 동봉한다 — 라이선스 전문은 `PretendardOFL.txt`.

## 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| M1 | 트레이 + 퀵캡처 + 로컬 큐 + PostgreSQL + 오늘 뷰 | ✅ 구현 (도그푸딩 중) |
| M2 | git 수집기 + 재개 카드 (`claude -p`) + GH/GL 이슈 | ✅ 구현 |
| M3 | 인박스 AI 분류 + 주간 리뷰 | ✅ 구현 |

주간 리뷰 초안 맨 위에는 그 주의 숫자가 한 줄로 붙는다 — 캡처·완료·커밋·재개 카드 열람·`claude -p` 호출 수·회의 시간. AI 호출을 세는 이유는 구독 한도를 Claude Code와 나눠 쓰기 때문이다(빈도를 조정할 근거).

git 수집은 `--all --no-merges --since=14days --author=<리포 user.email>`이다 — 브랜치를 가리지 않는 이유는 머지 전 작업도 한 일이고, auto-worklog(일일 업무일지)와 같은 커밋을 세야 같은 주를 두 문서가 다르게 세지 않기 때문이다.

주간 리뷰는 **주가 끝나면 스스로 만들어진다** — 하루 한 번 검사해 지난주 리뷰가 없거나, 있어도 그 주가 끝나기 전에 만든 초안이면(그 주의 절반만 담고 있다) 다시 만든다. 다 되면 그날 아침 브리핑 꼬리에 「지난주 리뷰 준비됨」이 한 번 붙는다. 트레이에서 직접 만들 수도 있다. 실패하면 그날은 다시 시도하지 않고 트레이·설정 탭에 이유가 뜬다.

주간 리뷰는 Obsidian 볼트의 `00_업무일지/YYYY년/MM월/00_주간리뷰_YYYY-Www.md`에 쓴다 — `AUTO:WEEKLY` 마커 안쪽만 갱신하므로 직접 덧붙인 메모는 남는다. 볼트 경로는 설정 탭에서 고르고(코드에 박아두지 않는다), 지정하지 않았으면 홈 아래에서 `00_업무일지` 폴더를 가진 곳을 한 번 찾아 쓴다. 끝까지 못 찾으면 초안은 DB에만 남고 리뷰 탭에서 그대로 볼 수 있다.
