결정 후보군

v0.1 피드백 ②③⑤에 대한 선택지 — 결정 완료(기록용): A = ①+③ 기본 + ② 옵션 · B-1 = Ctrl+Alt+Space(Claude 바인딩 해제) · B-2 = 2안 잠정 · C = 블루.

A. 캡처한 항목이 어느 프로젝트인지 아는 방법

셋은 배타적이지 않음 — 추천은 ①+③ 기본 탑재, ②는 파워유저 옵션. 어느 경우든 퀵캡처에 선택 UI는 추가하지 않는다(게이트 유지).

① 자동 컨텍스트 기록 ✓ 추천 (기본)

에디터 붙여넣기 버그 스텝 정리
📎 캡처 당시: GoWrite 리포에서 작업 중 (11:02, IDE 포그라운드) → AI 분류 근거로 사용
캡처 순간 포그라운드 창 제목 + 최근 커밋 리포를 조용히 메타데이터로 저장. 입력 비용 0, 인박스에서 힌트로 노출되고 AI 분류 정확도의 재료가 됨. 한계: 브라우저에서 캡처하면 추정 약함 — 그래서 ③과 병행.

② 인라인 토큰 (선택 입력)

W
웹훅 재시도 정책 답장 #ef
✓ eformsign으로 인식 — 인박스 건너뛰고 바로 todo로
입력 끝에 #약어(#ef, #gw, #sj…)를 치면 파싱해 즉시 분류. 쓰면 빠르고 안 쓰면 그만 — 강요 없음. 한계: 약어를 외워야 함. 프로젝트별 약어는 설정에서 지정.

③ AI 분류 제안 (설계 v1.0 그대로)

서식갤러리 검색 로그 이상치 살펴보기
✦ AI 제목 키워드 + ①의 컨텍스트로 서식갤러리 제안 → Y로 확정
인박스 정리 시점에 일괄 제안. ①의 메타데이터가 입력으로 들어가면 제목만 볼 때보다 정확도가 오름.

B. 단축키 후보

충돌 여부는 추정 — 확정 전 실사용 환경(JetBrains·터미널·브라우저)에서 확인 필요.

B-1. 전역 캡처 핫키

후보장점충돌 리스크 (추정)
Ctrl+Alt+Space ✓ 추천 주요 앱 바인딩 거의 없음, 왼손 한 뼘 낮음
Ctrl+Shift+Space 누르기 가장 편함 JetBrains 스마트 자동완성과 충돌 (.idea 사용 중이라 치명적)
Alt+` 한 손 최소 동작 JetBrains VCS 팝업과 충돌
Win+Shift+Space 앱 충돌은 없음 Win 조합은 OS가 선점 확장 중 — 향후 깨질 위험

B-2. 인박스 분류 키 세트

안키 배치장점단점
1안 니모닉 Y 제안 확정 · P 프로젝트 피커 · W 대기로 · D 마감 · X 삭제 영문 연상으로 외우기 쉬움 피커 열리는 만큼 손이 한 번 더 감
2안 숫자 다이렉트 ✓ 추천 Enter 제안 확정 · 1~9 프로젝트 즉시 지정 · W 대기 · X 삭제 피커 없이 한 키로 끝 — 가장 빠름. 프로젝트 5개 내외인 현 상황에 최적 순번 기억 필요 → 화면에 번호 상시 노출로 보완
3안 Vim 스타일 j/k 이동 · Enter 확정 · p 피커 · w 대기 · dd 삭제 터미널 근육기억 재활용 2키 조합(dd)은 과함. j/k 이동만 다른 안에 얹는 게 나음

공통(모든 안): ↑↓ 또는 jk 이동 · Space 완료 · 123 탭 전환 ← 2안 채택 시 탭 전환은 Tab 순환으로 변경 필요(숫자키 충돌)
